how we define "stale": a skill is marked stale when Cursor exposed it (listed its path in the <available_skills> block) in at least 10 sessions, and no session in Cursor, Codex, or Claude Code consulted it. Skills match by name (the directory containing SKILL.md), so the same skill installed under both ~/.cursor/skills/ and ~/.codex/skills/ counts as one.

What counts as consultation: we parse each transcript as structured JSON, not raw text. For Codex we keep only response_item.message events with role ∈ {user, assistant}; catalog injections live on role = developer and tool dumps live on function_call_output / exec_command_end, so they're dropped structurally. For Claude Code we keep only type ∈ {user, assistant}. Within retained events we drop any single event that names ≥4 distinct skills (assistant echoing the catalog). Bare-name matches (e.g. baz-pr-comments in prose) only count when the name matches an actually-installed skill.

Known blind spot: Cursor transcripts don't expose structured tool calls, so when Cursor silently follows a skill without quoting its path, we can't detect it. Stale means "no visible evidence anywhere we can see" - not "definitely unused". If a stale skill is genuinely load-bearing and rarely needed (a niche migration skill, for example), the cost is just description tokens in every Cursor session - which may be a tax worth paying.
